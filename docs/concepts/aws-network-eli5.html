AWS 網路架構 · 新手圖解

打造一個
私人社區

剛剛的 Terraform 到底蓋了什麼？沒碰過 AWS 網路也看得懂——用蓋一個社區的方式，帶你走一遍。

下面每一頁都是一張「施工藍圖」，對照的是 §4 項目 1、2 實際 apply 出來的 9 個資源。

SHEET 01 · 買地

先圍一塊地

AWS 裡任何人都能租房子，但預設大家共用同一條公共馬路。VPC 就是你自己圍起來的一塊地——圍牆一拉，裡面住什麼、誰能進來，全部自己說了算。

SHEET 02 · 分地基

地要分兩塊，蓋在不同街區

整塊地只蓋一棟房子太冒險——那條街停電，整個社區就斷線。所以拆成兩塊地基，蓋在兩個不同街區（Availability Zone）。之後要搬進來的資料庫、Kafka，官方規定就是至少要 2 個街區才准進駐，不是我們自己加碼。

SHEET 03 · 派警衛

大門先派一個警衛

Security Group 是社區大門口的警衛，決定誰能敲哪一戶的門。現在住戶都還沒搬進來，警衛手上目前只有一條規則；資料庫的門、Kafka 的門，等它們真的搬進來那天才會各自登記，不用現在就先猜。

SHEET 04 · 挖通道

兩條不出大門的地下通道

住戶常要去「S3 圖書館」借資料、去「Glue 檔案局」查目錄。與其每次繞出大門走公共馬路，不如私接一條通道直達——這叫 VPC Endpoint，但兩種蓋法完全不同。

Gateway 型 → S3

Interface 型 → Glue

SHEET 05 · 完整藍圖

組起來，長這樣

這就是這次 Terraform apply 真正在雲端蓋出來的東西——不是示意圖，9 個資源全部實際存在。

SHEET 06 · 施工意外

蓋的時候，撞到兩面牆

照著藍圖蓋，還是踢到兩個沒料到的規定。

✗ 街區 B 不存在

訂的地根本沒開發

每個 AWS 帳號的街區代號（a／b／c…）對應到的實際地點是隨機分配的——這個帳號壓根沒有「b 街區」，系統直接退件，只好改訂「c 街區」。

✗ 中文名牌被退

警衛只認英文

Security Group 的名牌（description）只吃 ASCII 字元，中文說明會被系統直接拒絕——名牌只好先改用英文，其他施工筆記照樣留中文。

SHEET 07 · 進度

現在蓋到哪了

地基完工，接下來是搬新住戶進來。
